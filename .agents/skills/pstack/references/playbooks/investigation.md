# Investigation

Use this for a read-only question about how a system works, why it was built a certain way, or which option is better. The deliverable is a cited answer or a recommendation, not a code change.

1. Route through the **how** skill. For motivation or history questions, also route through the **why** skill.
2. Separate observed facts from inferences, per `references/principles/fix-root-causes.md` where the question is about a failure.
3. For a choice between options, compare realistic alternatives with a tradeoffs table. Use a small experiment only when it can settle a factual uncertainty cheaply.
4. Write the reply per `references/writing/unslop.md`.
5. Do not edit code. If the investigation precedes a change, stop and re-route to Bug fix or Feature.

**Reply:** the `how`-shaped or `why`-shaped output, or a recommendation with a tradeoffs table. For "are we sure?" questions, give your real judgment with reasons. Push back if the premise is wrong.
